# dsh-sandbox-sweep

一个 **DSH 原生插件**：在 WebUI 侧栏脚部加两个按钮 —— **「清理沙箱痕迹」** 与 **「关闭DSH」**。
不依赖任何外挂手段（无用户脚本、无书签、无外部助手），也不改 DSH 源码。

## 先讲清楚：什么是「三件套」，它有什么危害

从 `0.1.7-alpha.1` 起，DSH 在 Windows 上用 **ACL + 完整性标签**实现沙箱。一个工作区第一次以
`workspace-write` 跑受限命令时，DSH 会对它的**根目录**做一次 `SetNamedSecurityInfoW`，一次写入三样
东西 —— 这就是「三件套」：

| 件 | 形态 | 它本来的作用 |
|---|---|---|
| **能力 SID 允许 ACE** | `S-1-4-x-y:(OI)(CI)(W,D,DC)` | 只给“由这个根的路径派生出的那个 SID”写入权（沙箱的工作方式） |
| **删除拒绝** | `Everyone:(CI)(DENY)(DC)` | 禁止删除该根下的子项（沙箱的自我保护） |
| **低完整性标签** | `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)` | 把整棵子树的完整性级别降到 Low |

**危害都出在“残留”上** —— `0.1.7` 正常退出时不会自动撤掉它们，异常退出（强杀 / 崩溃 / 断电）更是直接跳过：

- **删不掉东西**：`Everyone` 那条 `(DENY)(DC)` 是**可继承**的，会落到工作区里每一个子项上 —— 你在资源管理器里删工作区内的文件或目录会失败，而且看不出原因；
- **预览失败、弹「这些文件可能有害」**：低完整性标签会让 Explorer 对里面的文件（尤其 `.md`）预览不出来，或弹出提示；
- **会外溢**：标签带 `(OI)(CI)`，工作区里**新建**的文件会继承它；实例 temp 目录（`%TEMP%\dsh-<6位>`）也会被写同一套；
- **不会自己消失**：DSH 内部那套清理挂在它自己的 dispose 链上，而那条链在异常退出时不会被执行 —— 于是三件套留在磁盘上，越攒越多。

## 安装即知悉：本插件对安全性的影响

**它会做**（都是设计行为，不是故障）：

| 影响 | 说明 |
|---|---|
| **撤销三件套，把工作区根恢复成沙箱动它之前的样子** | 能力 ACE 撤销、`(DENY)(DC)` 移除、低标签清除。⚠️ 换句话说：**这等于去掉沙箱加在该根上的约束** —— 这正是本插件的目的，也是它必须由你**明确点击**才执行、绝不偷偷做的原因 |
| **会终止正在跑的对话与进程** | 两个按钮都会先停掉本实例所有会话正在跑的工作（回合 / 子智能体 / 后台作业 / 定时提醒），走的是**与按停止按钮相同的取消路径**，但**排队中的输入会被丢弃** |
| **会把所有会话切为只读** | 之后受限写入被拒，pwsh 掉进受限语言模式（`无法创建类型。此语言模式仅支持核心类型。`，`Add-Type`/COM/反射不可用）；`/permission workspace-write` 可切回 |
| **会直接删除实例 temp 目录（不可恢复）** | 只认严格命名 `dsh-<6位>`、无 `.lock` 且**闲置 ≥10 分钟**的根：启动 / 关闭时**直接删除，不走回收站**；关闭时还会删**本实例自己**那一个。有 `.lock` 或刚被碰过的，只在“本机最后一个实例”时才删。其它命名空间（`dsh-spill-*` / `dsh-subprocess-*` / `dsh-ssh-uploads`）一律不碰 |
| **会写台账** | `$DSH_HOME/sandbox-sweep/ledger.json`（逐根擦除结果 + 待擦项 + temp 清理清单，含 `trigger`）＋ `temp-baseline.json`（本实例启动时已存在的 temp 根，用来认“本次运行中新出现的”） |
| **擦除后本实例的受限写入会失败** | 实例内部的授权缓存不会自动重建；**重启实例即恢复** |

**它不会做**：

- **不动工作区里的任何文件内容**（只改根目录的 ACL，不删工作区里的任何文件）；
- **不需要管理员权限**：不提权、不装服务、不写注册表、不碰 DSH 安装树；
- **不发起任何网络请求**（只在本机调用 `icacls` / PowerShell 与 DSH 自身模块）；
- **不碰**别人的 home、别人的工作区、活动会话文件。

## 它还补上了 DSH 缺的那条「优雅关闭」

DSH 的 WebUI 本身**没有**「关闭本实例」的入口 —— 直接关窗口或从任务管理器杀掉，会**跳过刷盘与清理**，把三件套和 temp 目录留在磁盘上。本插件在侧栏补了这个入口，按固定顺序收尾：

```
门禁（拒绝新的自检／擦除请求）
  → 终止会话工作（回合 / 子智能体 / 后台作业 / 定时提醒）
  → 关闭常驻终端
  → 会话刷盘
  → 所有会话切只读
  →（默认开启）擦除工作区根上的三件套
  → 清理本实例自己的 temp 根
  → 退出进程
```

全程有报告：每一步成败、擦了几根、删了哪些目录、跳过了哪些（附原因）都会列出来，并附一份**可复制的原始自检报告**。

## 环境要求与适用性

| 项 | 说明 |
|---|---|
| 平台 | **Windows**。三件套是 Windows ACL + 完整性标签的产物；其它平台自检会失败并把原因弹窗告诉你 |
| DSH 版本 | **`0.1.7-alpha.1` 及以后会写三件套**的版本（工作区根 + 实例 temp 目录）。`0.1.5` 之类只写能力 ACE：插件对它们只做只读自检，清理是**空操作** |
| 权限 | 擦除要改工作区根的 ACL，**由宿主进程执行**（受限会话里对 ACL 的写入会被沙箱拒绝） |
| home | 只要求一个 DSH home（`$DSH_HOME`，未设置时是默认 `~/.dsh`）；插件在自己的 home 下写租约、台账与一份源码定位 |

## 安装 / 生效 / 卸载

1. **安装**：插件侧栏用「本地绝对路径」安装，或手工两步 —— 在 `<home>\profiles\<profile>\node_modules\` 下建符号链接指向本包，并在该 profile 的 `cordis.patch.yml` 里加：

   ```yaml
   - insert:
       - id: sandbox-sweep
         name: dsh-sandbox-sweep
   ```

2. **生效**：**重启该实例**。客户端 bundle 与宿主模块都在启动时装载 —— 刷新页面不够。
3. **卸载**：删掉符号链接 + 删掉 `cordis.patch.yml` 里那条即可；插件不写注册表、不起常驻服务、不碰 DSH 安装树。

## 交互规则（作者定的）

**什么时候会打扰你**：只在**检测到风险**时弹窗 —— ① 某个工作区 ACL 读不到（状态未知）；② 其他实例**确认**共用本工作区；③ 有机上其他活实例，**且**同机某个 home 登记过本工作区（无法归属，如实提示「无法排除」）；④ 进程枚举本身失败；⑤ 有正在跑的会话工作。弹窗里**没有勾选** —— 再点一次「清理」或「关闭DSH」就是接受；关窗 = Esc / 点遮罩 / 右上角 ×。

**什么时候完全不打扰你**：工作区**本来就没有沙箱痕迹**（能力 ACE / 删除拒绝 / 低标签三项全 false）**且临时区没有可清理的项**时，清理是**空操作** —— 不切只读、不终止会话、不弹窗，只弹一个气泡「无需清理：工作区没有沙箱痕迹」。有机上其他实例、但没有任何 home 登记过本工作区时，也**不弹窗**（对方用的是别的工作区）。无风险时直接执行，成功只弹气泡，失败才弹窗贴报告。

**看不懂就一定问你（兜底）**：报告结构不认识、宿主半版本比界面旧、自检里带了错误项、一个工作区都没列出来、或风险判定自己抛错 —— 这些「没枚举到的情况」一律**按风险弹窗**，绝不静默当成「没问题」。弹窗底部固定有一个「**原始自检报告（点开可复制）**」折叠块（报告 JSON + 原始响应 + 错误），点一下即全选，复制出来直接问 DSH 即可。

**跨实例判定的覆盖范围**：同机其他 DSH home 看两处 —— 启动器布局的兄弟 home（`homes/<版本>`）与**默认 home `~/.dsh`**。判定依据是对方租约声明的根（须进程存活）与各 home 的 `storages/workspace.json` 登记表；两边都不含本工作区 → 判为不共享，不打扰你。

## 现状

**已验证**（有实测证据，见 `docs/07-spike-results.md`）：

- 界面：两个按钮在侧栏脚部按规格渲染（展开态一行两枚 / 收起态上下排列），弹窗在默认窗口尺寸内不需滚动；
- 自检（宿主只读报告）：会话 / 终端 / 作业 / 工作区三件套状态 / 其他实例，均在真实实例内跑通；
- 擦除：6040 对象实验树全量 + 抽样通过，回读 `residue=[]`；台账落盘、启动补擦（种子 `pending`）验证通过；
- 权限回收：会话切 read-only，界面标签变为「仅可查看」；
- 优雅关闭：启动器日志记录 `意外退出（exit code: Some(0)）`（不是硬杀的 `Some(1)`）；
- 跨实例判定（含默认 `~/.dsh`）离线 11 项全绿；风险与兜底矩阵离线 **24 例**全绿；bundle 装载 + 弹窗渲染自检通过；
- **temp 分层清理**：关闭时删掉本实例自己的根（`own=True`）、启动时收掉闲置 ≥10 分钟的遗留根、别人的活跃根一律跳过 —— 两条路径都有台账阳性证据；
- 清理一次之后实测：工作区根**与其下条目三项全 false**，不留痕迹。

**尚未验证 / 做不到**：

- 浅色 / 深色两套主题下的对比度逐一核对；插件「禁用 / 回滚」演练；
- 常驻终端、作业 + 定时提醒、超大工作区耗时、并发点击 —— 留待真实场景观察；
- 点「清理」（而不是关闭）这条路，在“本机仅此实例”时的真实点击尚未验过（逻辑已由离线用例覆盖）。

## 来历

本插件是在 **DSH `0.1.5-rc.3`** 实例里、通过对话做出来的 —— 纯 VibeCoding：没有需求文档与测试团队，靠一轮轮实测迭代（也包含几次自我更正，见 `docs/07` 的 M11/M12）。它面向 **`0.1.7-alpha.1` 及以后会写三件套的版本**；`0.1.5` 只写能力 ACE，所以在它那儿“清理”多半是空操作。实测环境是 `0.1.7-rc.2`。

文档里提到「作者」时，指提需求、定交互规则并对结果拍板的人；改动与实测记录都在 `docs/07`。

## 三条不可违背的约束

1. **擦除只在「无隐患或隐患已被作者明确消除」之后发生**；任何可能影响擦除的情况都必须先告知作者，不符合条件就终止本次尝试。
2. **擦除不得与「实例继续以 workspace-write 运行」共存** —— 授权缓存不会自动重建，会留下「看起来正常、实际写不进去」的实例（见 `docs/04-risks-and-acceptance.md` R1）。
3. **退出前该做的必须都做完** —— 但**不要指望宿主的 dispose 链**：实测本插件的关闭路径拿不到 dispose 入口（实例日志里 `loader.dispose / root.dispose / fiber.dispose / scope.dispose` **四个全“不可用”**），所以 `sandbox-local` 那些注册在 `ctx.effect` 上的清理（撤销 temp 授权、删 temp 根）**不会执行**；实例 temp 必须由插件在 `process.exit()` **之前**自己收干净（见 `docs/07` 的 M12）。
