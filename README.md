# dsh-sandbox-sweep

为 DeepSeek Harness（DSH）补上「沙箱痕迹清理」与「优雅关闭」的 Windows 原生插件。

![Platform](https://img.shields.io/badge/platform-Windows-0078D4)
![DSH](https://img.shields.io/badge/DSH-%E2%89%A5_0.1.7--alpha.1-4B5563)
![License](https://img.shields.io/badge/license-MIT-green)
![Validated](https://img.shields.io/badge/validated-0.1.7--rc.2-2EA043)

> DSH 在 Windows 上以 `workspace-write` 运行沙箱后，会在**工作区根目录**和**实例临时目录**留下 ACL 与低完整性标签。
> 正常退出时这些设置不会自动撤销，异常退出（强杀 / 崩溃 / 断电）更是直接跳过 —— 结果是工作区里的文件**删不掉**、
> Explorer **预览失败或提示「这些文件可能有害」**，而且残留会越积越多。
> 本插件让你在 WebUI 里检查并清理这些残留，并给 DSH 补上一个完整的关闭流程。

## 功能

- 🧹 **清理沙箱痕迹** —— 检查当前实例涉及的工作区根，确认无冲突后撤销沙箱写入的 ACL 与完整性标签；工作区**本来就没有痕迹**时是空操作，只弹一个气泡。
- 🧹 **按版本自动分流（v8 / v10）** —— 只在**真的会写三件套**的宿主上显示「清理沙箱痕迹」；更早的宿主只保留「关闭DSH」，不做多余操作。判据有两层：① 宿主版本 ≥ `0.1.7-alpha.1`；② **沙箱没有被本地插件 `dsh-sandbox-legacy-acl` 接管**（那个插件把 `0.1.7-rc.x` 的沙箱换回 0.1.5 行为：授权只写能力 ACE，不写删除拒绝、不写完整性格标签）。两层任一不满足都只保留优雅退出 —— 否则会出现「点了清理、提示成功、其实无物可擦」的误报。
- ⏻ **优雅关闭 DSH** —— DSH 的 WebUI 本身没有「关闭本实例」入口；本插件按固定顺序收尾：停止任务 → 关闭常驻终端 → 会话刷盘 → 擦除痕迹 → 清理本实例 temp → 退出进程。
- 🔍 **风险前置检查** —— 清理前会查：其他实例是否共用同一工作区、是否有正在跑的会话工作、工作区 ACL 能否读取；有风险才弹确认框。
- 📋 **可复制的报告** —— 每一步的成败、擦了哪些根、删了哪些目录、跳过了什么（附原因）都列出来，并附一份可复制的原始自检报告。
- 🛡️ **本地运行** —— 不提权、不装服务、不写注册表、不碰 DSH 安装树、**不发起网络请求**；只在本机调用 `icacls` / PowerShell 与 DSH 自身模块。

## 兼容性

| 项 | 要求 |
|---|---|
| 系统 | **Windows**（三件套是 Windows ACL + 完整性标签的产物；其它平台自检会失败并说明原因） |
| DSH 版本 | **`0.1.7-alpha.1` 及以后会写三件套的版本**：显示两个按钮。更早的版本（如 `0.1.5-rc.x`）只写能力 ACE、而那属于平台的复用缓存 → 界面**只显示「关闭DSH」**，不做清理、不做任何 ACL 操作（v8 起按版本自动分流） |
| 沙箱实现 | **v10 起多一条前置条件**：若本实例 home 下的 `sandbox-legacy-acl/report.json` 表明沙箱已被 **`dsh-sandbox-legacy-acl`** 接管（`status: "installed"` 且 `enabled: true`），则无论宿主版本多新，都按上面那一档处理（只保留优雅退出）。该文件不存在 / 读不到 / 解析失败 / 字段不是这两个值 → **保守回退**到按宿主版本判 |
| 权限 | 不需要管理员权限；擦除由 **DSH 宿主进程**执行（受限会话里对 ACL 的写入会被沙箱拒绝） |
| home | 一个 DSH home（`$DSH_HOME`，未设置时为默认 `~/.dsh`）；插件在自己的 home 下写租约与台账 |

## 安装

### 方法一：DSH 插件界面（推荐）

1. 下载或 clone 本仓库到本机；
2. 打开 DSH → 侧栏插件页 → 选择「本地绝对路径」安装；
3. 选择本仓库目录；
4. **重启该实例**。

### 方法二：手动安装

在 `<home>\profiles\<profile>\node_modules\` 下建一个指向本仓库的符号链接，并在该 profile 的 `cordis.patch.yml` 里加：

```yaml
- insert:
    - id: sandbox-sweep
      name: dsh-sandbox-sweep
```

> [!IMPORTANT]
> 装完**必须重启实例**：客户端 bundle 与宿主模块都在启动时装载，刷新 WebUI 不会重新加载。

### 卸载

删掉符号链接与 `cordis.patch.yml` 里那条即可。插件不写注册表、不起常驻服务、不碰 DSH 安装树。

## 使用

安装并重启后，WebUI 侧栏脚部会出现两个按钮：

### 清理沙箱痕迹

检查当前实例涉及的工作区根与实例 temp 目录，确认没有潜在冲突后清理沙箱残留：撤销能力 ACE、移除 `Everyone` 删除拒绝、清除低完整性标签；顺带收掉满足条件（严格命名、闲置 ≥10 分钟、无人使用）的实例 temp 根。工作区干净且临时区无可清理项时，只弹一个「无需清理」气泡，不切只读、不终止会话。

### 关闭 DSH

按固定顺序结束本实例：停止正在跑的会话工作 → 关闭常驻终端 → 会话刷盘 →（默认）擦除沙箱痕迹 → 清理本实例自己的 temp 根 → 退出进程（v7 起不再"切只读"：进程随即退出、令牌随进程消失，这一步没有独立价值）。全程有报告，失败项会写进台账供下次启动补做。

## ⚠️ 安全说明

> [!WARNING]
> **清理之后，本实例的受限写入会失败**：插件撤销了工作区根上的沙箱授权，而实例内部的授权缓存不会自动重建。
> **重启该实例即恢复** —— 这也是插件不自动清理、必须由你点击触发的原因之一。

### 它会做什么

| 行为 | 说明 |
|---|---|
| **擦除沙箱痕迹** | 只擦**会碍事的两件**：移除 `Everyone:(CI)(DENY)(DC)`（否则「删子文件夹」被拒）与低完整性标签（否则跨等级移动被拦、图标与预览异常）。**能力 ACE 一律保留**：它是平台的跨会话复用缓存 —— 撤掉会让正在用同一工作区的**其他实例立刻写不进去**，也会让下一次授权重传整棵树。保留后的状态与「只有 0.1.5 沙箱跑过」一致 |
| **终止正在跑的会话工作** | 两个按钮都会先停掉本实例所有会话的工作（回合 / 子智能体 / 后台作业 / 定时提醒），走的是与「停止」按钮相同的取消路径；**排队中的输入会被丢弃** |
| **把所有会话切为只读** | 之后受限写入被拒、pwsh 进入受限语言模式；`/permission workspace-write` 可切回 |
| **删除实例 temp 目录（不可恢复）** | 只认严格命名 `dsh-<6位>`、无 `.lock` 且闲置 ≥10 分钟的根，在启动 / 关闭时**直接删除，不走回收站**；关闭时还会删本实例自己那一个。即便判定为「本机最后一个实例」，也**仍要求闲置 ≥10 分钟**（只放宽 `.lock` 一项）；**被同机活实例在租约里声明**的根一律不碰。`dsh-spill-*` / `dsh-subprocess-*` / `dsh-ssh-uploads` 一律不碰 |
| **写台账** | `$DSH_HOME/sandbox-sweep/ledger.json`（逐根擦除结果 + 待擦项 + temp 清理清单）与 `temp-baseline.json`（本实例启动时已存在的 temp 根） |

### 它不会做什么

> [!IMPORTANT]
> 清理**只改工作区根目录的 ACL**，不删除、不修改工作区里的任何文件。

- **不需要管理员权限**：不提权、不装服务、不写注册表、不碰 DSH 安装树；
- **不发起任何网络请求**（只在本机调用 `icacls` / PowerShell 与 DSH 自身模块）；
- **不碰**别人的 home、别人的工作区、活动会话文件。

## 为什么需要这个插件

DSH 从 `0.1.7-alpha.1` 起在 Windows 上用 **ACL + 完整性标签**实现沙箱。一个工作区第一次以 `workspace-write` 跑受限命令时，DSH 会对它的**根目录**做一次 `SetNamedSecurityInfoW`，一次写入三类 Windows 安全设置（下文简称**三件套**）：

| 类型 | Windows 表现 | 用途 |
|---|---|---|
| 能力 SID 允许 ACE | `S-1-4-x-y:(OI)(CI)(W,D,DC)` | 只给「由该根路径派生出的那个 SID」写入权（沙箱的工作方式） |
| 删除拒绝 | `Everyone:(CI)(DENY)(DC)` | 禁止删除该根下的子项（沙箱自我保护） |
| 低完整性标签 | `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)` | 把整棵子树的完整性级别降到 Low |

### 残留之后会发生什么

- **文件删不掉**：`Everyone` 的 `(DENY)(DC)` 可继承，会落到工作区里每一个子项上 —— 在资源管理器里删工作区内的文件或目录会失败，而且看不出原因；
- **预览失败 / 提示「这些文件可能有害」**：低完整性标签会让 Explorer 对里面的文件（尤其 `.md`）预览不出来或弹出提示；
- **会外溢**：标签带 `(OI)(CI)`，工作区里**新建**的文件会继承它；实例 temp 目录（`%TEMP%\dsh-<6位>`）也会被写同一套；
- **不会自己消失**：DSH 内部那套清理挂在它自己的 dispose 链上，异常退出时不会被执行 —— 残留就此留在磁盘上。

## 工作原理

**清理流程**：只读自检 → 风险判定（必要时弹确认）→ 终止会话工作 → 所有会话切只读 → 撤销能力 ACE / 清除低标签 → 移除 `Everyone` 删除拒绝 → 回读校验 `residue=[]` → 写台账（失败项标记 `pending`，下次启动补做）。

**关闭流程**（DSH WebUI 本身没有「关闭本实例」入口，直接关窗口或强杀会跳过刷盘与清理）：

```
门禁（拒绝新的自检／擦除请求）
  → 终止会话工作（回合 / 子智能体 / 后台作业 / 定时提醒）
  → 关闭常驻终端
  → 会话刷盘
  → 所有会话切只读
  →（默认开启）擦除工作区根上的删除拒绝与低标签（能力 ACE 保留）
  → 清理本实例自己的 temp 根
  → 退出进程
```

**启动清扫**：实例启动 3 秒后自动跑一次，处理三类遗留 —— 硬杀 / 崩溃留下的脏根、台账里的 `pending`、满足条件的实例 temp 根；不弹窗，只写台账与日志。

更细的配方、顺序陷阱与判据（含「为什么撤除必须 SID 匹配」「为什么 temp 用删除而不是擦除」）见 `docs/03-architecture.md` 与 `docs/07-spike-results.md`。

## 交互规则（摘要）

- **无风险**：直接执行，成功只弹一个 3 秒气泡，不打断你；
- **有风险**（工作区 ACL 读不到 / 其他实例确认共用同一工作区 / 有活实例且同机某个 home 登记过该工作区 / 进程枚举失败 / 有正在跑的会话工作）：弹窗列出风险，**弹窗里没有勾选项** —— 再点一次按钮即视为接受，关窗 = Esc / 点遮罩 / 右上角 ×；
- **无法可靠判断时默认请求确认**：报告结构不认识、宿主版本比界面旧、自检自带错误项等，一律按风险弹窗，绝不静默当成「没问题」，并在弹窗底部附一份可复制的原始自检报告。

完整状态机与全部文案见 `docs/02-ux-and-flows.md`。

## 设计原则

1. 状态不明确时**不自动清理**（宁可弹窗问你）；
2. 清理之后**不允许当前实例继续假装可写**；
3. 退出之前**把该做的本地清理做完** —— 且不指望宿主的 dispose 链：实测本插件的关闭路径拿不到 dispose 入口（`loader/root/fiber/scope.dispose` 四个全不可用），所以实例 temp 由插件自己在 `process.exit()` 之前收干净。

工程侧完整约束见 `docs/03-architecture.md`，agent 视角见 `AGENTS.md`。
