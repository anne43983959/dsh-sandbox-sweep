# dsh-sandbox-sweep

一个 **DSH 原生插件**：在 WebUI 侧栏加两个按钮，处理 Windows 沙箱留在工作区上的「低完整性三件套」，
并让实例能被**优雅关闭**。不依赖任何外挂手段（无用户脚本、无书签、无外部助手），也不改 DSH 源码。

| 按钮 | 作用 |
|---|---|
| **清理沙箱痕迹** | 自检 →（只在有风险时问你）→ 终止本实例正在跑的工作 → 所有会话切只读 → 擦除三件套 → 回读校验 |
| **关闭DSH** | 自检 →（只在有风险时问你）→ 终止工作 → 刷盘 →（可选）擦除 → 走宿主 dispose 链优雅退出本实例 |

实现形态：一个插件包，含**宿主半**（Node：路由 / ACL / 会话与关闭）与**客户端半**（浏览器：按钮 / 弹窗 / 气泡）。
界面座位是侧栏脚部的 `sidebar.footer.action`（list 型）。

## 环境要求与适用性

| 项 | 说明 |
|---|---|
| 平台 | **Windows**。三件套是 Windows ACL + 完整性标签的产物；其他平台自检会失败并把原因弹窗告诉你 |
| DSH 版本 | **0.1.7-alpha.1 及以后会写三件套**（工作区根 + 实例 temp 目录）。0.1.5 之类不写三件套：插件对它们只做只读自检，清理是**空操作** |
| 权限 | 擦除要改工作区根的 ACL，**由宿主进程执行**（受限会话里对 ACL 的写入会被沙箱拒绝） |
| home | 只要求一个 DSH home（`$DSH_HOME`，未设置时是默认 `~/.dsh`）；插件在自己的 home 下写租约、台账与一份源码定位 |

## 安装 / 生效 / 卸载

1. **安装**：插件侧栏用「本地绝对路径」安装，或手工两步——在 `<home>\profiles\<profile>\node_modules\` 下建符号链接指向本包，并在该 profile 的 `cordis.patch.yml` 里加：

   ```yaml
   - insert:
       - id: sandbox-sweep
         name: dsh-sandbox-sweep
   ```

2. **生效**：**重启该实例**。客户端 bundle 与宿主模块都在启动时装载——刷新页面不够。
3. **卸载**：删掉符号链接 + 删掉 `cordis.patch.yml` 里那条即可；插件不写注册表、不起常驻服务、不碰 DSH 安装树。

## 安装即知悉：本插件会造成什么影响

安装本插件即表示你已知悉并接受下列**设计行为**（它们是功能，不是故障）：

| 影响 | 说明 |
|---|---|
| **会终止正在跑的对话与进程** | 「清理沙箱痕迹」与「关闭DSH」都会先停掉本实例所有会话正在跑的工作（回合、子智能体、后台作业、定时提醒）——用的是**与用户按停止按钮相同的取消路径**（`agent.cancel({ kind: 'user' })`），但**排队中的输入会被丢弃**（keepInbox 关闭） |
| **会把所有会话切为只读** | 之后受限写入被拒；pwsh 会掉进受限语言模式（`无法创建类型。此语言模式仅支持核心类型。`，`Add-Type`/COM/反射不可用）。用 `/permission workspace-write` 可切回 |
| **会改动工作区 ACL** | 擦除三件套：能力 SID 允许 ACE、`Everyone:(CI)(DENY)(DC)` 删除拒绝、低完整性标签。**不删除任何文件** |
| **擦除后本实例的受限写入会失败** | 实例内部的授权缓存不会自动重建；**重启实例即恢复** |
| **会写台账** | `$DSH_HOME/sandbox-sweep/ledger.json`（模式回收记录 + 逐根擦除结果 + 待擦项）；下次启动自动补擦未通过校验的根 |
| **不会撤销实例私有 temp 目录** | 本版本没有对插件开放的宿主 dispose 入口；tmpdir 下的 `dsh-*` 是惰性垃圾（随机路径、能力 SID 只写在自身），与工作区无关 |

## 交互规则（用户定的）

**什么时候会打扰你**：只在**检测到风险**时弹窗——① 某个工作区 ACL 读不到（状态未知）；② 其他实例**确认**共用本工作区；③ 有机上其他活实例，**且**同机某个 home 登记过本工作区（无法归属，如实提示「无法排除」）；④ 进程枚举本身失败；⑤ 有正在跑的会话工作。弹窗里**没有勾选**——再点一次「清理」或「关闭DSH」就是接受；关窗 = Esc / 点遮罩 / 右上角 ×。

**什么时候完全不打扰你**：工作区**本来就没有沙箱痕迹**（能力 ACE / 删除拒绝 / 低标签三项全 false）时，清理是**空操作**——不切只读、不终止会话、不弹窗，只弹一个气泡「无需清理：工作区没有沙箱痕迹」。有机上其他实例、但没有任何 home 登记过本工作区时，也**不弹窗**（对方用的是别的工作区）。无风险时直接执行，成功只弹气泡，失败才弹窗贴报告。

**看不懂就一定问你（兜底）**：报告结构不认识、宿主半版本比界面旧、自检里带了错误项、一个工作区都没列出来、或风险判定自己抛错——这些「没枚举到的情况」一律**按风险弹窗**，绝不静默当成「没问题」。弹窗底部固定有一个「**原始自检报告（点开可复制）**」折叠块（报告 JSON + 原始响应 + 错误），点一下即全选，复制出来直接问 DSH 即可。

**跨实例判定的覆盖范围**：同机其他 DSH home 看两处——启动器布局的兄弟 home（`homes/<版本>`）与**默认 home `~/.dsh`**（DSH 未设 `$DSH_HOME` 时的 home）。判定依据是对方租约声明的根（须进程存活）与各 home 的 `storages/workspace.json` 登记表；两边都不含本工作区 → 判为不共享，不打扰你。

## 现状

**已验证**（有实测证据，见 `docs/07-spike-results.md`）：

- 界面：两个按钮在侧栏脚部按规格渲染（展开态一行两枚 / 收起态上下排列），弹窗在默认窗口尺寸内不需滚动；
- 自检（宿主只读报告）：会话 / 终端 / 作业 / 工作区三件套状态 / 其他实例，均在真实实例内跑通；
- 擦除：6040 对象实验树全量 + 抽样通过，回读 `residue=[]`；台账落盘、启动补擦（种子 `pending`）验证通过；
- 权限回收：会话切 read-only，界面标签变为「仅可查看」；
- 优雅关闭：启动器日志记录 `意外退出（exit code: Some(0)）`（不是硬杀的 `Some(1)`）；
- 跨实例判定（含默认 `~/.dsh`）离线 11 项全绿；风险与兜底矩阵离线 21 例全绿；bundle 装载 + 弹窗渲染自检通过；
- 「没枚举到的情况」一律弹窗，且原始报告始终可复制。

**尚未验证 / 做不到**：

- 浅色 / 深色两套主题下的对比度逐一核对；插件「禁用 / 回滚」演练；
- 常驻终端、作业 + 定时提醒、超大工作区耗时、并发点击——留待真实场景观察；
- 「退出后实例私有 `dsh-*` temp 目录消失」**做不到**：本版本没有对插件开放的宿主 dispose 入口（`loader/root/fiber/scope.dispose` 均不可用），那些目录是惰性垃圾。

## 三条不可违背的约束

1. **擦除只在「无隐患或隐患已被用户明确消除」之后发生**；任何可能影响擦除的情况都必须先告知用户，不符合条件就终止本次尝试。
2. **擦除不得与「实例继续以 workspace-write 运行」共存**——授权缓存不会自动重建，会留下「看起来正常、实际写不进去」的实例（见 `docs/04-risks-and-acceptance.md` R1）。
3. **退出必须走宿主自身的 dispose 链**，不能在清擦前直接 `process.exit()`，否则 temp 授权与 temp 目录清理会被跳过。
